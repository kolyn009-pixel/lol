ОБНОВЛЕНИЕ TUTORBOT — ЭТАП 1

ВАЖНО
- Сначала остановите текущего бота.
- Сделайте копию живой tutor.db и всей папки проекта.
- В SERVER-архив намеренно НЕ входят tutor.db, credentials.json и token.json.

1. Распакуйте SERVER-архив поверх текущей папки проекта.
2. Установите дополнительную зависимость для Excel-экспорта:
   python3 -m pip install -r requirements_stage1.txt
3. Проверьте синтаксис:
   python3 -m py_compile *.py core/*.py
4. Выполните локальную самопроверку БД:
   python3 core/post_update_check.py
5. Проверьте живое подключение Google Calendar:
   python3 calendar_test.py
6. Запустите бота тем же способом, которым он был запущен ранее.
7. Проверьте /start, /admin и /system.

НОВОЕ В ЭТАПЕ 1
- Модульная папка core/ вместо дальнейшего разрастания bot.py/admin.py.
- Один владелец + несколько дополнительных администраторов.
- Системный журнал действий.
- Неизменяемый финансовый журнал.
- Финансы: «получено», «заработано», «предоплачено, но не отработано».
- «Входящие» / центр событий.
- Режим технических работ с подтверждением включения/выключения.
- Диагностика целостности БД, балансов, расписания и локального состояния Google Calendar.
- Ручной backup из Telegram и автоматический backup.
- Excel-экспорт учеников, занятий и оплат.
- Критические ошибки попадают в центр событий и отправляются владельцу.
- post-update self-check и скрипты безопасного backup/rollback.

АДМИНИСТРАТОРЫ
/system -> «Администраторы»
/addadmin TELEGRAM_ID Имя
/deladmin TELEGRAM_ID
Добавлять и отзывать администраторов может только владелец.

БЕЗОПАСНОЕ ОБНОВЛЕНИЕ
sh core/safe_update.sh /путь/к/боту

ОТКАТ
sh core/rollback.sh /путь/к/боту

Google Calendar:
core/post_update_check.py проверяет локальную целостность данных.
Реальный API Google проверяется отдельно через calendar_test.py на сервере.
