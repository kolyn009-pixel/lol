# CLAUDE.md — правила работы с проектом Adelia

Adelia — учебная CRM: Telegram- и VK-бот, веб-портал, оплаты, расписание, домашние задания, ИИ-ассистент. Python.

## Начальник: как распределять работу
Основная сессия Claude — начальник. Субагенты лежат в `.claude/agents/`.
- **Крупная задача** → сначала `tech-lead` (план), потом исполнители по плану.
- **Любая правка кода** → после неё `tester`, перед мержем `reviewer`.
- **Правки в payments.py, admin.py, ролях, авторизации** → дополнительно `security` и `payments-qa`.
- **Изменение таблиц БД** → только через `db-migrations`.
- **Расписание и уведомления** → проверяет `timezones`.
- **Новая функция бота** → проверяет `vk-tg-parity`.
- **Идеи** (`product`, `competitor-scout`, `ux-researcher`) → только по явному запросу пользователя.
- **Релиз и выкладка, удаление веток, закрытие PR, тег** → только после явного «да» пользователя.

Типичная цепочка: `tech-lead` → исполнитель → `tester` → `reviewer`.

## Бюджет токенов (обязательно)
- Одновременно не больше 2–3 агентов.
- Модели: haiku для простых задач (cleaner, tester, deps, docs, branch-janitor), sonnet для обычных, opus только для refactor, security, reviewer и tech-lead.
- Огромные файлы (bot.py, database.py, admin.py по 200+ КБ) целиком не читать: сначала Grep, потом Read нужного диапазона строк.
- Перед большой задачей дать короткий план и дождаться «да».
- Не перезапускать агента ради того же результата; если агент упал дважды, остановиться и спросить пользователя.
- Ответы агентов краткие: таблицы и списки, без пересказа кода.

## Правила кода
- Не ломать обратную совместимость БД и старые импорты.
- Секреты только в переменных окружения.
- Тексты для пользователей — по BRAND_ADELIA.md.
- Изменения делать в отдельной ветке, мержить через PR.
