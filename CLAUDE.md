# CLAUDE.md — правила работы с проектом Adelia

Adelia — онлайн-школа физики (ОГЭ, ЕГЭ, школьная программа 7–11 класса): Telegram- и VK-бот, веб-кабинеты ученика/родителя/учителя, лендинг, десктоп (Electron), оплаты (чеки, Robokassa), расписание, домашние задания, ИИ-ассистент. Python, SQLite, ванильный JS без сборщика.

Два формата занятий: **индивидуальные** и **в мини-группах**. Курс — это программа (ОГЭ, ЕГЭ, 7–9, 10–11), формат — способ заниматься по ней. Любая новая функция учитывает оба формата.

Рабочая ветка с актуальным кодом: `feat/public-group-registration-20261111`. `main` устарел (сентябрь) — от него не ветвиться.

## Команды агентов (`.claude/agents/`)

Основная сессия — диспетчер: запускает агентов, сама большие задачи не делает.

| Команда | Ведущий | Исполнители и проверка |
|---|---|---|
| Контроль | **efficiency-lead** | бриф до задачи, проверка и журнал после |
| Дизайн | **design-lead** | ui-builder, ux-texts, design-qa, ux-researcher |
| Бэкенд | **backend-lead** | api-dev, integrations, db-migrations, perf, timezones |
| Тестирование | **qa-lead** | tester, test-writer, e2e-tester, bot-flow-tester, payments-qa, design-qa |
| Безопасность | **security-lead** | security (аудит кода), secrets-guard, infra-security, privacy-guard |
| Маркетинг | **marketing-lead** | seo-specialist, content-writer, marketing-analyst, competitor-scout |
| Будущие обновления | **roadmap-lead** | product, idea-critic, feasibility-reviewer, competitor-scout, ux-researcher |
| Общие | tech-lead (задачи на несколько команд) | reviewer, refactor, cleaner, docs, deps, branch-janitor, release, ai-assistant, vk-tg-parity |

Цепочка для любой задачи команды:
1. `efficiency-lead` — бриф: агенты, модели, что читать, лимиты шагов, что параллельно.
2. Ведущий (`design-lead` / `backend-lead`) — план или контракт.
3. Исполнители — строго по брифу.
4. Проверка: `qa-lead` составляет план тестов; деньги, права, вход, персональные данные — дополнительно `security-lead`.
5. `reviewer` — перед мержем.
6. `efficiency-lead` — проверка расхода и запись в `docs/agent-budget-log.md`.

Мелкая правка в один-два файла — без цепочки, сразу исполнитель + tester.

## Отдел будущих обновлений

Идеи владельцу приносит только roadmap-lead и только после внутреннего обсуждения: product предлагает → idea-critic разбирает → feasibility-reviewer оценивает → roadmap-lead отбирает 3–5 здравых. Итог — `docs/roadmap/`. Сырые идеи владельцу не отправлять.

## Бюджет токенов (обязательно)

- Не больше 3 агентов одновременно.
- Модели: haiku — механика, поиск, проверки; sonnet — обычная работа; opus — только design-lead, backend-lead, security-lead, tech-lead, security, refactor, reviewer и сложные слияния.
- Лимит вызовов инструментов на агента: haiku ≤15, sonnet ≤30, opus ≤40. Не хватает — задача слишком большая, дробить.
- Большие файлы (bot.py, database.py, admin.py, payments.py ~100–270 КБ, web/*.css) целиком не читать: grep, затем Read нужного диапазона.
- Агент, который упёрся в неясность, останавливается и возвращает вопрос, а не гадает.
- Не перезапускать агента ради того же результата; дважды упал — стоп, спросить человека.
- Ответы агентов — таблицы и списки, без пересказа кода.
- После каждой задачи команды — строка в `docs/agent-budget-log.md` (заполняет efficiency-lead по usage из отчётов).

## Дизайн-система «Аделия» (стиль «Журнал»)

Источник правды — `web/tokens.css`; брендбук — артефакт «Аделия — дизайн-система».
- Бумага `--paper` #FFFFFF, чернила `--ink` #111111, один акцент `--accent` #5B3CC4 (1–2 места на экран).
- Заголовки Playfair Display (курсивное слово акцентом), текст Inter.
- Линейки вместо карточек; без теней и скруглений (кроме аватаров); подписи-капсом «01 / Раздел».
- Без ИИ-штампов: градиенты, свечения, эмодзи-иконки, бенто.
- Новый CSS — в отдельном файле страницы; старые `*_cleanN.css` не трогать, `!important` не добавлять.

## Деньги, роли, безопасность

- Подтверждение оплат — только из допустимых статусов, в транзакции `BEGIN IMMEDIATE`; лимит промокода перепроверяется при подтверждении (превышен — отказ).
- Сбой зачисления минут повторяет `retry_uncredited_payments()` (при старте и раз в 10 минут).
- Админские права — только OWNER и ADMIN; TESTER — нет. Владелец — `OWNER_ID` из окружения.
- Секреты только в окружении (`/etc/tutorbot.env`, `/etc/tutorbot/*.env`).

## Постоянство

Агенты и правила живут в репозитории (`.claude/agents/`, этот файл, `docs/`). Любая сессия Claude Code в папке проекта — на Mac, на сервере или в облаке с подключённым репозиторием — подхватывает их автоматически. Новые агенты добавлять сюда же, через PR. Журнал расхода — `docs/agent-budget-log.md`, стратегия маркетинга — `docs/marketing/`, модель угроз — `docs/security/`.

## Продакшн и деплой (важно)

- Сервер: сервисы `tutorbot`, `tutorbot-web`, `tutorbot-vk`, `adelia-*` работают из `/opt/adelia-current` — это **симлинк на релиз** в `/opt/adelia-releases/`. Живая база — `/opt/tutorbot/tutor.db`. nginx: `/` из `/var/www/adeliatutor.ru`, `/app/` = `/opt/adelia-current/web/`, `/api/` → 127.0.0.1:8876 (`/api/health`).
- На сервере **нет git в релизе**, и живой код может отличаться от любой ветки: установщики ставили части обновлений напрямую (например `web_backend/teacher_push_queue.py`, `web_backend/receipt_accounting.py` есть только на сервере).
- Никогда не делать `git pull` и не копировать ветку целиком на сервер. Порядок обновления:
  1. Сравнить файлы обновления с живыми; отличающиеся — снимком в ветку `server-live-snapshot-<дата>` (с сервера: `git -C /opt/tutorbot` + worktree в /tmp).
  2. Трёхстороннее слияние: снимок + изменения → ветка обновления.
  3. Скрипт `/root/adelia_update.sh`: копия текущего релиза → `git apply --check` патча → py_compile → бэкап базы через sqlite3 backup → вопрос `yes` → атомарное переключение симлинка → рестарт → health-check → автооткат.
- Главную страницу сайта (`/var/www/adeliatutor.ru/index.html`) переключать только по явному «да» владельца.

## Правила кода

- Не ломать обратную совместимость БД и старые импорты; миграции идемпотентные.
- Тексты для пользователей — голос Аделии (BRAND_ADELIA.md): женский род, ученику «ты», родителю «Вы», без канцелярита.
- Изменения — в отдельной ветке от рабочей, мерж после tester и reviewer.
