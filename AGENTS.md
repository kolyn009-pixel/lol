# «Аделия» в Codex

«Аделия» — онлайн-школа физики с веб-кабинетами, десктопным приложением, Telegram- и VK-ботами. При изменениях обучения, расписания и оплаты учитывай индивидуальные занятия и мини-группы. Сохраняй совместимость старых данных SQLite и импортов. Миграции должны быть идемпотентными.

Перед изменениями интерфейса сверяйся с `web/tokens.css` и разделом «Дизайн-система» в `CLAUDE.md`. Для текстов используй `BRAND_ADELIA.md`. При работе с оплатой, ролями или деплоем учитывай соответствующие разделы `CLAUDE.md` и проверяй актуальное состояние по коду и разрешённому окружению. Продакшн, публикации и внешние действия требуют отдельного поручения.

## Роли Codex

Определения лежат в `.codex/agents/`. В доверенной рабочей копии Codex загружает конфигурацию проекта при старте сессии. Модель агенты наследуют из сессии. Глубина рассуждения задана для каждой роли.

| Направление | Ведущий | Исполнители и проверка |
|---|---|---|
| Координация | `efficiency-lead` | `tech-lead`, `reviewer` |
| Дизайн и интерфейс | `design-lead` | `ui-builder`, `ux-texts`, `design-qa`, `ux-researcher` |
| Бэкенд | `backend-lead` | `api-dev`, `integrations`, `db-migrations`, `perf`, `timezones`, `ai-assistant`, `vk-tg-parity` |
| Тестирование | `qa-lead` | `tester`, `test-writer`, `e2e-tester`, `bot-flow-tester`, `payments-qa` |
| Безопасность | `security-lead` | `security`, `infra-security`, `privacy-guard` |
| Маркетинг | `marketing-lead` | `seo-specialist`, `content-writer`, `marketing-analyst`, `competitor-scout` |
| Дорожная карта | `roadmap-lead` | `product`, `idea-critic`, `feasibility-reviewer` |
| Сопровождение | `release` | `branch-janitor`, `cleaner`, `deps`, `docs`, `refactor` |

## Как делегировать

- Основная сессия распределяет работу и отвечает за итог. Для небольшой правки выбери одну подходящую роль и запусти целевую проверку. Для крупной задачи привлеки `efficiency-lead` для брифа и профильного ведущего для плана. Задачи на стыке команд помогает разбить `tech-lead`.
- Дай каждому агенту цель, границы файлов и критерий готовности. Запускай параллельно только независимые задачи, максимум три агента. Назначай изменения в одном файле одному исполнителю.
- По завершении попроси независимое ревью существенных изменений. Для оплат, входа, прав доступа и персональных данных добавь профильную проверку. Используй существующие тесты и временные данные. Основная сессия сверяет выводы и проверяет итоговый diff.
- Для больших файлов начни с `rg` и читай нужные диапазоны. Для многошаговых задач фиксируй расход в `docs/agent-budget-log.md`, если журнал ведётся для этой задачи. Записывай только доступные метрики.

Пример запроса: «Разберись, почему кабинет учителя не открывается. Поручи `e2e-tester` проверить вход и загрузку страницы, а `api-dev` — проследить серверную обработку запроса. После исправления попроси `reviewer` проверить diff».
