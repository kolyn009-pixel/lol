# Аделия: что довести перед выпуском

Состояние на 01.10.2026. Это приоритеты и результаты проверки кода, а не подтверждение готовности production.

## Уже подготовлено в PR #4

- QR Сбера удалён из кабинета родителя и вкладки преподавателя. Старые image/upload API отвечают 410, status сообщает configured=false. Сохранённые серверные файлы не удаляются.
- В поездке преподаватель выбирает «Мой регион» через часы или расписание. Экран «Сегодня», календарные дни недели, ближайшие занятия и карточка занятия используют выбранный пояс. Например, 19:00 Москвы — 23:00 Бангкока; 23:30 Москвы — 03:30 следующего дня в Бангкоке. Моменты уроков в базе не меняются.
- Смена рабочего пояса для записи отделена от изменения отображения. Поле переноса подписано поясом расписания, чтобы случайно не перенести занятие из-за поездки.
- Robokassa выключена до подключения магазина. Реальная выдача чеков НПД требует проверки с сервисом СМЗ после активации.
- Локальные тесты покрывают подписи/суммы, повторные callbacks, сохранение использованных минут, тестовый режим, отменённый урок и смену календарного дня/недели при поездке. Проверена конвертация старых времён без UTC-смещения независимо от пояса устройства, включая переходы летнего времени.

## Что улучшить следующим, не добавляя разделов

1. **Завершение оплаты.** В существующей карточке показывать «Проверяем оплату», «Оплачено» или понятное действие при ошибке. После возврата из банка обновлять статус автоматически; не предлагать повторную оплату при задержке callback. Для счетов REVIEW нужна заметная задача с переходом к конкретному платежу.
2. **Продолжение работы после сбоя.** После истечения сессии возвращать человека к открытому уроку/счёту. При потере сети сохранять черновик сообщения и заметки; не терять введённое при обновлении интерфейса. Показывать состояние конкретной отправки, а не только общую плашку сети.
3. **Спокойное обновление PWA.** Одно уведомление «Доступна новая версия» после окончания занятия или отправки черновика. Версия в существующем экране состояния, чтобы быстро отличать старый кэш от серверной ошибки.
4. **Меньше визуального шума.** Оставить по одному главному действию для каждой роли: ученику ближайший урок/ДЗ, родителю актуальный счёт, преподавателю текущий урок и действительно срочные задачи. Повторяющиеся подписи и статистику перенести в уже имеющиеся подробности.

## Условия выпуска

- Завершить фактическую схему атомарного развёртывания: постоянные пути SQLite/файлов всех шести служб, резервная копия, откат ссылки /opt/adelia-current. Dirty-копию /opt/tutorbot не сбрасывать. Изоляцию второго сайта сохранить.
- Пройти один полный сценарий каждой роли в браузере и на телефоне: вход, занятие, сообщение с файлом, ДЗ, оплата и обновление статуса. Отдельно проверить преподавателя в Москве/Бангкоке и ученика в Самаре.
- Подключить тестовый магазин Robokassa; после активации согласовать контрольную боевую оплату и проверить настоящий чек НПД. Не считать локальные подписи заменой проверки провайдера. Возвраты, booking drafts и получение ссылки чека в Аделию имеют ограничения, описанные в ROBOKASSA_SMZ.md.
- Подтвердить сборку и запуск установщиков macOS/Windows на самих системах. Ранее native smoke test, подпись/нотариализация и полноценный CI не были подтверждены.

До выполнения этих пунктов разумный формат — ограниченная бета с небольшим числом семей. Новые большие функции перед первым выпуском увеличат объём проверки без решения основных рисков.
