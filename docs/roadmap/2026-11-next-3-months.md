# Будущие обновления: декабрь 2026 — февраль 2027

Раунд отдела от 20.11.2026: product предложил 8 идей → idea-critic разобрал → feasibility-reviewer проверил по коду → roadmap-lead отобрал. Тема: расти и подготовиться к найму с сентября 2027.

Общее правило, принятое по итогам спора: **бюджет сообщений родителю** — от Аделии не чаще одного «необязательного» сообщения в неделю (уроки и оплаты не считаются). Все идеи ниже его соблюдают.

## Отобрано (4)

### 1. Месячный отчёт родителю — по расписанию, в одно действие · S–M
- **Проблема.** Прозрачность для родителя — ядро оффера и главный страх аудитории, но отчёт сейчас собирается только вручную по команде в боте. С найме каждый новый преподаватель повторит этот ручной труд.
- **Решение.** 1-го числа Аделия сама собирает черновики (занятия, минуты, домашки, темы) по каждому ученику; преподаватель видит список «к отправке», просматривает и отправляет одним действием. Без автоотправки без просмотра. Для групп — строго по одному ребёнку.
- **Польза.** Родителю — видимый результат и доверие; преподавателю — минус ручная работа; масштабируется на найм.
- **Что сказал критик и как учтено.** Риск неточностей и обещаний в тексте → в черновике только факты из базы, без ИИ-«оценок»; просьба об отзыве — не в отчёте, а отдельно и только после согласия владельца.
- **Что уже есть.** `automation/monthly_reports.py` (`build`, `save_draft`, журнал отправок) — подключён к боту вручную. Нет запуска по расписанию и паритета VK.
- **Первый шаг.** Джоб «1-го числа — черновики» + счётчик «отчётов к отправке» на новом экране «Сегодня» в кабинете.

### 2. Воронка заявок: откуда пришли и чем закончилось · S–M
- **Проблема.** Не видно, какой канал даёт оплаты — без этого любые решения о продвижении вслепую.
- **Решение.** Заявка на пробное сохраняет UTM и «откуда узнали»; статусы выводятся сами из данных (заявка → пробный назначен → проведён → оплата), руками ничего не ведётся. Владельцу — таблица (сначала выгрузка, потом экран) + 2–3 числа: заявки за неделю, места в группах.
- **Польза.** Решения по SEO, Профи.ру, соцсетям и рекламе — на цифрах.
- **Критик → учтено.** Дублировало задачу маркетинга про UTM → делаем одной задачей вместе с marketing-analyst; персональные данные заявителей в таблице ограничены, срок хранения как у заявок.
- **Что есть.** Статусы заявок на пробное уже есть (NEW → ACCEPTED → TRIAL_COMPLETED); нет UTM, «откуда узнали» и связи с оплатой.
- **Первый шаг.** Поля `utm_*` и «откуда узнали» в форме нового лендинга и в заявке.

### 3. «Кому написать на этой неделе» внутри «Требует внимания» · M
- **Проблема.** Отток и неявки замечаются поздно; при одном преподавателе удержать ученика дешевле, чем найти нового.
- **Решение.** Не отдельный экран, а новые строки в блоке «Требует внимания» кабинета (не больше 5): кончаются минуты, пропуски подряд, давно нет домашки, пробный завтра без подтверждения. У каждой — готовый черновик сообщения голосом Аделии, отправка по кнопке.
- **Критик → учтено.** Было два отдельных списка (неявки пробных и «спящие») и риск второго списка рядом с первым → объединено в один блок; лимит длины; общий бюджет сообщений.
- **Что есть.** `balance_forecast`, `student_history`; напоминания о начале пробного нет — первым шагом напоминание только преподавателю (у заявителя с сайта не всегда есть канал связи).
- **Первый шаг.** После этапа 1 плана кабинета (`/api/teacher/today`) — добавить эти источники в «внимание».

### 4. Аудит готовности к найму · S (исследование)
- **Проблема.** В сентябре придёт второй преподаватель; если код рассчитан на одного, найм упрётся в разработку в самый горячий месяц.
- **Решение.** После этапа 0 плана кабинета (teacher_id) — таблица «место / что зашито на одного преподавателя / объём / к какому месяцу нужно»: выплаты, права, передача ученика, выбор преподавателя при записи, имя Николая Владимировича в текстах бота, цены и пакеты, ИИ-подсказки.
- **Критик → учтено.** Не повторять уже найденное в плане кабинета; результат — таблица решений для владельца, а не «список на полке». Срок — к марту.
