# Аделия 0.3.0 — подготовка выпуска

Подготовлены исходники и сборка трёх пакетов: Windows x64, macOS Intel x64 и macOS Apple Silicon arm64. Бинарные пакеты этой версии ещё не собраны. Публикация не выполнялась.

## Календарь занятий

Раздел «Расписание» открывает календарь: месяц, неделя или список. На телефоне исходный вид — список. Есть переход к сегодняшнему дню, поиск ученика/группы, предмет и статусы. Даты и время используют существующую настройку региона преподавателя. Отдельный цвет и подпись отмечают перенесённое занятие. Групповые занятия берутся только из реально созданных записей, регулярные будущие даты не выдумываются.

Индивидуальная запись открывает существующую карточку занятия; групповая — расписание группы. Создание, перенос и отмена продолжают использовать текущие бизнес-правила. Рабочие часы доступны отдельной кнопкой, с возвратом в календарь и предупреждением о несохранённом редактировании.

Данные добавлены в существующий защищённый CRM GET, поле `items` для старых клиентов сохранено. Новые поля `calendar_items` и `calendar_limit_reached` не меняют занятия или деньги. При достижении лимита выводится предупреждение вместо молчаливого неполного календаря.

## Сборка на Intel Mac

Использовать отдельный чистый checkout зафиксированного коммита. Нужны Node.js >=22 и работающий Docker Desktop. Запустить `bash scripts/build_all_on_intel_mac.sh`.

Скрипт сначала проверяет загрузку Windows builder из Docker Hub (три попытки), запускает существующие проверки и проверки календаря, собирает обе Mac-архитектуры и Windows через Wine. Затем проверяет SHA-512 файлов каждого пакета и создаёт три ZIP, SHA256SUMS и release-set.json. В конце должен появиться `ALL_DESKTOP_BUILDS_OK` и папка `Desktop/Adelia-0.3.0-<12 знаков SHA>`.

Нельзя переименовывать beta-пакеты в 0.3.0. Новая сборка содержит собственную версию и исходный SHA.

## Установка календаря и интерфейса на сервер

Из изолированной выгрузки того же коммита:

```
python3 scripts/install_release_ui.py --root /opt/adelia-current
python3 scripts/install_release_ui.py --root /opt/adelia-current --apply
```

Установщик проверяет фрагменты подключения календаря до записи, сохраняет посторонние правки HTML/manifest, создаёт резервную копию, проверяет веб-сервис и совпадение опубликованных CSS/JS/manifest с исходниками. Если локальный код отличается, остановиться и разобрать конфликт. Переносы/очистка Google из отдельного предыдущего обновления устанавливаются его собственным установщиком, если ещё не применены.

## Загрузка пакетов

На Mac, подставив фактическую папку вывода:

```
ssh root@72.56.18.8 'mkdir -p /root/adelia-upload/0.3.0-<SHA12>'
scp "$adelia_output"/{macos-x64.zip,macos-arm64.zip,win-x64.zip,SHA256SUMS,release-set.json} root@72.56.18.8:/root/adelia-upload/0.3.0-<SHA12>/
```

На сервере из исходников того же выпуска:

```
python3 scripts/publish_uploaded_desktop.py --git-sha <ПОЛНЫЙ_SHA> --bridge-beta
python3 scripts/publish_uploaded_desktop.py --git-sha <ПОЛНЫЙ_SHA> --bridge-beta --apply
```

Первая команда только проверяет и очищает временную подготовку после выхода. Вторая публикует в `/var/www/adeliatutor.ru/desktop-updates/stable/` и создаёт совместимый beta-канал на те же бинарные файлы для текущих пользователей. Каждая ссылка канала переключает сразу три платформы. При ошибке HTTP откатываются обе ссылки и ссылки скачивания. Nginx не редактируется.

Новое приложение по умолчанию проверяет stable-канал (`latest.yml`/`latest-mac.yml`). Старый beta Mac видит manifest с channel=beta и версией 0.3.0, Windows — beta.yml с той же версией. После установки приложение проверяет stable. Windows сохраняет механизм differentialPackage, Mac — проверенную ручную замену DMG с предложением убрать загруженный файл. Минимальный размер обновления и бесшовная замена Mac не обещаются.

## Проверки перед массовым распространением

Автоматически проверены модель календаря, границы дат и часовые пояса, фильтры, существующие действия, сохранение совместимости API, публикация stable+beta и откат при ошибке HTTP на изолированных фикстурах. Полная `npm run selftest` и native-сборки выполняются на Mac сборочным скриптом; в текущей Linux-среде без Docker они не выполнялись.

После сборки нужно открыть приложение на Intel Mac и Windows: вход, календарь/рабочие часы, чат с вложением, открытие занятия, доска/Телемост с камерой и микрофоном, завершение занятия. Пакет arm64 следует проверить на Apple Silicon. Реальное обнаружение обновления текущими beta-клиентами проверяется после публикации.

Mac не подписан и не нотарифицирован Apple: package.json сохраняет identity=null. Системная проверка установки может потребовать дополнительных действий пользователя. Для публичного распространения без этого шага нужен Apple Developer и подписанный выпуск.
