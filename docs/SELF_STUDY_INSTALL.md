# Установка личного обучения

Статус: код подготовлен для интеграции. Проверки базы/API выполнялись на временной
базе. Реальный браузер, микрофон, ИИ и установленное приложение ещё требуют приёмки.
Нельзя считать новый модуль полностью проверенным или установленным на сервере.

## Перед установкой

Нужны два разных каталога: исходники ветки
`feat/personal-language-study-stage1-20261027` и фактический рабочий release.
Не заменять весь сервер содержимым ветки: там могут быть более свежие рабочие правки.
Точечный установщик переносит только учебные модули, добавляет маршруты API и assets
в HTML, сохраняя остальной кабинет. Он отклоняет незнакомую структуру API и конфликты.

Определить фактические значения:

- `LIVE_RELEASE`: каталог, из которого работает веб-процесс; если используется
  `/opt/adelia-current`, разрешить ссылку до текущего release.
- `PRODUCTION_DB`: SQLite-файл, который реально использует `database.connect()`
  в окружении этого веб-процесса. Установщик не угадывает его по имени.
- `WEB_SERVICE`: systemd-сервис веб-API.
- `LOCAL_API`: loopback URL с портом. В репозитории и старых инструкциях встречаются
  разные порты, поэтому брать порт из текущего сервиса, а не из примера.

## Проверка без изменений

Из каталога новых исходников:

```sh
python scripts/self_study_selftest.py
python scripts/self_study_practice_selftest.py
python scripts/self_study_feedback_selftest.py
python scripts/self_study_scenes_selftest.py
python scripts/self_study_install_selftest.py
python scripts/self_study_student_selftest.py
node scripts/self_study_ui_selftest.cjs
```

Для последней команды нужны Playwright и установленный Chromium. Тесты используют
временную базу и искусственный локальный вход, не рабочие учётные записи.

Точечная проверка совместимости с серверным release, без записи файлов:

```sh
python scripts/install_self_study.py --root "$LIVE_RELEASE" --database "$PRODUCTION_DB" --service "$WEB_SERVICE" --health-url "$LOCAL_API"
```

Переменные обозначают предварительно проверенные пути и настройки. Команда показывает
список изменяемых файлов. Отказ из-за конфликта требует разбора исходников; не удалять
проверки и не заменять рабочие файлы вслепую.

## Применение после приёмки

```sh
python scripts/install_self_study.py --root "$LIVE_RELEASE" --database "$PRODUCTION_DB" --service "$WEB_SERVICE" --health-url "$LOCAL_API" --apply
```

Нужны права на release, базу и перезапуск сервиса. Установщик создаёт закрытый каталог
резервной копии рядом с release, использует SQLite backup API, меняет файлы атомарно,
перезапускает сервис и проверяет `/api/health` и отказ в доступе к учебному API без
сессии (401). При ошибке возвращает исходные файлы и перезапускает прежний код.
Схема учебных таблиц создаётся при использовании модуля; существующие таблицы
учеников и финансов не изменяются. Успешный health check не заменяет вход преподавателя.

## Проверка после установки

Войти обычным способом и проверить: открытие раздела, урок и черновик с повторным
входом, проверку ответов, появление выражений, контрольную и её черновик, сохранение
сцены, запись/воспроизведение/скачивание, диктовку или понятное сообщение об отсутствии
поддержки, ИИ-разбор и понятную ошибку при ненастроенном провайдере. Повторить в
приложении и на узком экране. Не менять права входа для облегчения проверки.

## Откат

Использовать путь резервной копии, который напечатал установщик:

```sh
python scripts/install_self_study.py --root "$LIVE_RELEASE" --service "$WEB_SERVICE" --rollback "$STUDY_BACKUP" --apply
```

Откат восстанавливает только код. Он сохраняет новые учебные записи и не подменяет
живую базу старой копией. Если после установки файлы изменялись, автоматический откат
откажется, чтобы не затереть последующую работу. Данные требуют отдельной процедуры
восстановления только при подтверждённой необходимости.

Новые web-assets также включены в desktop manifest для следующей сборки приложения.
Сборка установщиков и выпуск новой версии приложения этой командой не выполняются.

## Ученический режим

В ученическом кабинете добавляется ссылка на /app/self-study.html. Она использует
обычную сессию ученика, а не права преподавателя. Проверь отдельным входом: видны
английский и испанский, диагностика меняет только собственный маршрут, учитель
по-прежнему видит свои три языка и прежние результаты. Новые desktop-исключения
попадут в следующую сборку; установленное приложение нужно проверить отдельно.

## Приглашения только в языковой раздел

После установки войти владельцем, открыть «Моё обучение → Семья · доступ к языкам».
Выбрать точный существующий аккаунт по имени, роли и ID. Для мамы/папы выбрать
«родитель». Скопировать персональную ссылку и передать человеку. Ему нужно войти
именно под выбранным аккаунтом, затем открыть ссылку. Если входа ещё нет, пройти
обычный вход в ученический или родительский кабинет и снова открыть приглашение.
Токен нельзя публиковать. Любое новое приглашение для того же аккаунта отменяет
прежнее. Отзыв доступа применяется только к языкам, не к рабочим кабинетам.
Все обычные ученики без приглашения получат отказ только на языковых маршрутах.
Проверить родителя и ребёнка с одинаковым числовым ID: результаты должны различаться.

## Настройка каждого члена семьи

После активации человек открывает «Выбрать курсы и настроить программу».
Для брата выбрать английский, возрастную группу и собственную цель B1 к концу
7 класса; дату указать по фактическому учебному году. Сестры выбирают свои
языки и уровни отдельно, в том числе немецкий C1 как самооценку. Мама/папа
выбирают свои цели; шаблон EN/ES не обязателен. Изменение опроса сохраняет
прежние результаты. Полнота материалов и необходимость диагностики видны
в курсе; личный опрос не означает, что весь курс автоматически создан.

## Приёмка интенсивного блока

Запустить python scripts/self_study_intensive_selftest.py. В браузере открыть
новый модуль (enx-/dex-/esx-/fax-), проверить цель и этапы, синтетическую озвучку
и сообщение при отсутствии голоса, короткий письменный черновик, восстановление
его на том же устройстве, самопроверку и перенос. Самооценка не должна менять
контрольные баллы. Рабочие кабинеты должны оставаться доступными как прежде.


### Ежедневное занятие с сохранением места

«Начать сегодня» выбирает время в пределах бюджета выбранного языка,
незавершённый черновик либо первый ещё не освоенный модуль. При наличии
карточек и блоке от 15 минут добавляет повторение. Английский с неизвестной
стартовой точкой у семейного аккаунта сначала направляет на диагностику.
Материал фиксируется на время занятия; смена устройства не меняет шаг.
План, пауза и результаты хранятся в отдельной personal_study_sessions.
Оптимистическая версия защищает от двойного перехода и устаревшего экрана.

Этап заданий требует новой сохранённой проверки именно этого модуля; этап
повторения — оценённой карточки того же языка после старта занятия либо
явного пропуска. Понимание и устный перенос остаются самооценками. Ошибки
ниже порога оставляют модуль непройденным для следующего подбора.
Когда стартовые материалы закончились, сообщение о закреплении сохраняется
и после возобновления. Долги и сброс за пропущенные дни не создаются.
Это последовательность на выбранное время, не календарь повторных встреч,
не оценка всех четырёх навыков и не полный курс до любого уровня CEFR.
Голосовые записи по-прежнему локальные, между устройствами не переносятся.

Проверка этапа: 16 новых серверных тестов; общий набор — 123 теста.
Браузерный сценарий дополнен стартом, паузой, перезагрузкой и запретом
перехода без проверки, но его запуск ещё не подтверждён.


### Словарь и обязательная семейная диагностика

Для каждого выбранного языка EN/DE/ES/FA у семейного аккаунта обязательна
короткая стартовая проверка до учебных запросов. ROOT, настройки, приглашения
и сами проверки доступны до её завершения. Сервер блокирует прямые ссылки
на уроки/карточки/контрольные/сцены, пока остаётся непроверенный выбранный язык.
OWNER освобождён; может пройти проверку добровольно. Старый английский тест
зачитывается, но не закрывает остальные языки. Новый язык в настройках
требует только своей проверки. Родитель и ученик с одинаковым ID независимы.

В банке 71 оригинальное стартовое задание: EN 23, DE/ES/FA по 16. Есть
вариант «Не знаю», последовательный экран и черновик ответов в этой вкладке.
Ориентир A0–B2 выводится по последовательным группам заданий; это авторская
маршрутизация, не валидированный CEFR placement exam. C1, аудирование, речь
и письмо этим тестом не подтверждаются. Рекомендация — конкретное действие
на четыре недели и дата пересмотра, с временем из личного бюджета. Пользователь
может подставить предложенную цель в форму и сохранить её; до этого личная
цель/дедлайн не заменяются. Для начинающего немецкого добавлены шесть
оригинальных базовых модулей (24 задания). Общая база — 63 модуля / 252 задания;
длинные программы и мосты между уровнями всё ещё требуют наполнения.

Слова и выражения из подходящего стартового маршрута можно добавлять
дневными порциями. Цель — объём колоды и дата; это не число выученных слов
и не оценка уровня. Первоначально предлагается до 30 выражений на ближайшие
четыре недели, либо меньше при ограниченном банке/раннем дедлайне курса.
Порция рассчитывается по остатку, дате и бюджету (1–10 новых карточек).
При большом числе повторений новое приостанавливается, при частых ошибках
уменьшается. Неиспользованные дни не накапливаются. Обновление дня — UTC.

Добавление транзакционное: не более одной порции в день на аккаунт/язык,
в том числе при параллельных кликах и смене цели после добавления. Сначала
показано выражение, значение можно открыть; затем — воспроизведение через
существующую очередь интервальных повторений. Уже имеющиеся выражения
не выдаются повторно; последующий урок не дублирует словарную карточку.
При нехватке банка или времени интерфейс показывает ограничение.

Новые таблицы personal_study_placement, personal_study_word_goals,
personal_study_word_days относятся только к языкам. Рабочие роли/функции
и боты не менялись. 153 локальных теста проходят, включая 16 тестов
диагностики и 14 словаря. Браузерный сценарий расширен семейным входом
через проверки; фактический браузерный прогон и живой сервер не подтверждены.


### Проверка семейного пути через HTTP

Стенд теперь направляет GET-запросы всех трёх ролей в API: раньше
ученические и родительские GET могли получать HTML-заглушку. Новый
scripts/self_study_http_selftest.py проверяет через настоящий локальный
HTTP-сервер приглашение, обязательные тесты, настройки, начало/паузу/возврат,
проверку урока, завершение, дневной словарь, интервальный повтор, отзыв
и изоляцию ролей с одинаковым ID. Идентификация cookie role используется
только в одноразовом стенде, не в приложении.

Исправлен срок пересмотра цели: четыре недели считаются от сохранённой
даты проверки, включая старую английскую проверку, а не от каждого
открытия страницы. Показывается, когда пора пересмотреть ближайшую цель.
Время на язык при этом может обновляться вслед за настройками.

162 локальных теста проходят (добавлены восемь HTTP-сценариев и проверка
фиксированной даты цели). Сценарий Playwright обновлён и сохраняет
HTML/скриншот/ошибку при сбое, если указан каталог артефактов. Фактический
браузерный прогон по-прежнему не подтверждён: в среде отсутствует Chromium.
Проверки микрофона, реального ИИ, PWA/desktop и живого сервера не подменяются
HTTP-тестами. Сервер не обновлялся.
