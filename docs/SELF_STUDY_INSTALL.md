# Установка личного обучения

Статус: код подготовлен для интеграции. Проверки базы/API выполнялись на временной
базе. Реальный браузер, микрофон, ИИ и установленное приложение ещё требуют приёмки.
Нельзя считать новый модуль полностью проверенным или установленным на сервере.

## Перед установкой

Нужны два разных каталога: исходники ветки
`feat/personal-language-study-stage1-20261027` и фактический рабочий release.
Не заменять весь сервер содержимым ветки: там могут быть более свежие рабочие правки.
Точечный установщик переносит только учебные модули, добавляет маршруты API и assets
в HTML, сохраняя остальной кабинет. Он отклоняет незнакомую структуру API и конфликты.

Определить фактические значения:

- `LIVE_RELEASE`: каталог, из которого работает веб-процесс; если используется
  `/opt/adelia-current`, разрешить ссылку до текущего release.
- `PRODUCTION_DB`: SQLite-файл, который реально использует `database.connect()`
  в окружении этого веб-процесса. Установщик не угадывает его по имени.
- `WEB_SERVICE`: systemd-сервис веб-API.
- `LOCAL_API`: loopback URL с портом. В репозитории и старых инструкциях встречаются
  разные порты, поэтому брать порт из текущего сервиса, а не из примера.

## Проверка без изменений

Из каталога новых исходников:

```sh
python scripts/self_study_selftest.py
python scripts/self_study_practice_selftest.py
python scripts/self_study_feedback_selftest.py
python scripts/self_study_scenes_selftest.py
python scripts/self_study_install_selftest.py
node scripts/self_study_ui_selftest.cjs
```

Для последней команды нужны Playwright и установленный Chromium. Тесты используют
временную базу и искусственный локальный вход, не рабочие учётные записи.

Точечная проверка совместимости с серверным release, без записи файлов:

```sh
python scripts/install_self_study.py --root "$LIVE_RELEASE" --database "$PRODUCTION_DB" --service "$WEB_SERVICE" --health-url "$LOCAL_API"
```

Переменные обозначают предварительно проверенные пути и настройки. Команда показывает
список изменяемых файлов. Отказ из-за конфликта требует разбора исходников; не удалять
проверки и не заменять рабочие файлы вслепую.

## Применение после приёмки

```sh
python scripts/install_self_study.py --root "$LIVE_RELEASE" --database "$PRODUCTION_DB" --service "$WEB_SERVICE" --health-url "$LOCAL_API" --apply
```

Нужны права на release, базу и перезапуск сервиса. Установщик создаёт закрытый каталог
резервной копии рядом с release, использует SQLite backup API, меняет файлы атомарно,
перезапускает сервис и проверяет `/api/health` и отказ в доступе к учебному API без
сессии (401). При ошибке возвращает исходные файлы и перезапускает прежний код.
Схема учебных таблиц создаётся при использовании модуля; существующие таблицы
учеников и финансов не изменяются. Успешный health check не заменяет вход преподавателя.

## Проверка после установки

Войти обычным способом и проверить: открытие раздела, урок и черновик с повторным
входом, проверку ответов, появление выражений, контрольную и её черновик, сохранение
сцены, запись/воспроизведение/скачивание, диктовку или понятное сообщение об отсутствии
поддержки, ИИ-разбор и понятную ошибку при ненастроенном провайдере. Повторить в
приложении и на узком экране. Не менять права входа для облегчения проверки.

## Откат

Использовать путь резервной копии, который напечатал установщик:

```sh
python scripts/install_self_study.py --root "$LIVE_RELEASE" --service "$WEB_SERVICE" --rollback "$STUDY_BACKUP" --apply
```

Откат восстанавливает только код. Он сохраняет новые учебные записи и не подменяет
живую базу старой копией. Если после установки файлы изменялись, автоматический откат
откажется, чтобы не затереть последующую работу. Данные требуют отдельной процедуры
восстановления только при подтверждённой необходимости.

Новые web-assets также включены в desktop manifest для следующей сборки приложения.
Сборка установщиков и выпуск новой версии приложения этой командой не выполняются.
